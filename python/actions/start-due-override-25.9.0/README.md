# ftrack 批量日期编辑器 (Start Due Override)

一个 ftrack Action 插件，用于批量编辑任务和里程碑的开始日期和截止日期，支持非工作日设置和智能日期管理。

## 🌟 功能特色

### 1. **智能批量编辑**

- 支持同时选择多个任务（Task）和里程碑（Milestone）进行批量日期编辑
- 智能识别选中实体的当前日期状态，自动显示合适的默认值
- 当选中实体日期相同时显示具体日期，不同时显示空白提示用户输入

### 2. **非工作日支持**

- **突破 ftrack 默认限制**：允许将日期设置到周末和节假日
- 不受 ftrack 工作日历限制，提供更灵活的项目排期

### 3. **项目范围自动约束**

- 自动获取项目的开始和结束日期范围
- 智能将用户输入的日期限制在项目范围内，防止设置无效日期
- 当日期超出项目范围时自动调整并记录日志

### 4. **Milestone 特殊处理**

- 自动识别 Milestone 实体类型
- 智能跳过 Milestone 的 `start_date` 赋值（因为它是不可变的，自动等于 `end_date`）
- 在界面显示时自动过滤 Milestone 的 `start_date`，避免用户困惑

### 5. **灵活的空值处理**

- 支持 `'null'` 值表示用户不想设置该日期字段
- 支持 `'...'` 占位符表示多个不同值需要用户输入
- 智能识别并保持空值状态，不进行无效赋值

### 6. **用户友好的界面**

- 简洁直观的日期选择界面
- 中文标签和提示信息
- 智能默认值显示，减少用户输入工作量

## 🚀 使用方法

### 1. 安装部署

```bash
# 将脚本放置到 ftrack 的 action 目录
cp start_due_override.py /path/to/ftrack/actions/

# 或者通过 ftrack Connect 加载
# 将整个目录放置到 Connect 的插件目录中
```

### 2. 在 ftrack 中使用

#### 步骤 1：选择实体

- 在 ftrack 项目中选择一个或多个任务（Task）或里程碑（Milestone）
- 可以混合选择不同类型的实体

#### 步骤 2：启动 Action

- 右键点击选中的实体
- 在 Actions 菜单中选择 **"批量编辑 开始、截止 日期"**

#### 步骤 3：查看智能默认值

- **相同日期场景**：如果所有选中实体的某个日期字段都相同，输入框会自动显示该日期
- **不同日期场景**：如果选中实体的日期字段不同，输入框显示为空，提示您输入新值
- **无日期场景**：如果实体没有设置日期，输入框显示为空

#### 步骤 4：设置日期

- **开始日期**：设置任务的开始日期（Milestone 会自动跳过）
- **截止日期**：设置任务或里程碑的截止日期
- 可以只设置其中一个字段，另一个保持不变

#### 步骤 5：确认执行

- 点击确认按钮执行批量编辑
- 系统会自动处理日期约束和实体类型适配

### 3. 智能显示逻辑示例

#### 场景 1：所有实体日期相同

```
选中实体：Task A (start: January 15, 2025), Task B (start: January 15, 2025)
界面显示：开始日期输入框显示 "January 15, 2025"
用户操作：可以修改为新日期，或保持不变
```

#### 场景 2：实体日期不同

```
选中实体：Task A (start: January 15, 2025), Task B (start: January 20, 2025)
界面显示：开始日期输入框为空
用户操作：需要输入新的统一日期
```

#### 场景 3：混合场景

```
选中实体：Task A (start: January 15, 2025), Task B (start: null)
界面显示：开始日期输入框为空
用户操作：输入日期将应用到所有选中实体
```

### 4. 特殊值处理

| 输入值     | 含义                  | 处理方式                               |
| ---------- | --------------------- | -------------------------------------- |
| `具体日期` | 如 `January 15, 2025` | 设置为指定日期（会被约束到项目范围内） |
| `空值`     | 不修改该日期字段      | 保持原值不变，跳过赋值                 |

### 5. 典型使用场景

#### 场景 1：批量设置项目里程碑

```
选择：多个 Milestone
设置：截止日期 = March 15, 2025
结果：所有里程碑的截止日期统一设置，开始日期自动同步
```

#### 场景 2：批量调整任务时间

```
选择：多个 Task
设置：开始日期 = February 01, 2025，截止日期 = February 28, 2025
结果：所有任务的时间范围统一调整
```

#### 场景 3：部分日期调整

```
选择：多个 Task（开始日期各不相同）
设置：只设置截止日期 = April 30, 2025，开始日期留空
结果：只有截止日期被统一设置，开始日期保持原值
```

## 🆚 与默认功能对比

| 特性           | ftrack 默认 | 本插件              |
| -------------- | ----------- | ------------------- |
| 非工作日设置   | ❌ 不支持   | ✅ 完全支持         |
| 批量编辑       | ⚠️ 有限支持 | ✅ 智能批量编辑     |
| Milestone 处理 | ⚠️ 容易出错 | ✅ 智能识别和处理   |
| 日期约束       | ❌ 手动检查 | ✅ 自动项目范围约束 |
| 空值处理       | ⚠️ 基础支持 | ✅ 灵活的空值策略   |

## ⚠️ 注意事项

1. **Milestone 限制**：Milestone 的 `start_date` 是不可变的，系统会自动跳过
2. **项目范围**：所有日期都会被自动约束在项目的开始和结束日期范围内
3. **权限要求**：需要对选中实体有编辑权限
